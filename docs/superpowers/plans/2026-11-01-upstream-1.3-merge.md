# Upstream 1.3 Merge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Merge all 247 upstream commits (`simbasjungles/free-my-tv` at `a9e1027`) into mahitTV, so its history is caught up and it gains upstream's TV fixes and data sources, while it keeps looking and behaving as it does today.

**Architecture:** One merge commit that keeps mahitTV's redesigned files whole, followed by small ordinary commits that bring upstream's fixes across, one feature at a time. Each commit passes `tools/check.sh`, and you can stop after any task with a working app. The merge commit moves the merge base to `a9e1027`, so the next upstream pull only shows what's new.

**Tech Stack:** Java (Android, no Gradle: `build.sh`), ES5 web app (`web/`), Python 3 tools, Node + Playwright tests.

**Spec:** None separate. Feature Decisions and the Commit Ledger below are the spec.

## Why this shape (trial results, 2026-11-01)

All trials ran in a scratch folder on the real commits; no project file changed.

| Approach tried | Result |
|---|---|
| Plain merge | 51 conflicted files: 26 catalogues, 3 icons, 22 code/config |
| Take mahitTV's side of each conflict only (`-X ours`) | 319 compile errors, 295 of them in `HomeView`, `SettingsActivity`, `Recs`: upstream's auto-merged lines need code from the hunks thrown away |
| Keep the redesigned files whole | 0 compile errors after removing dropped features; all Android suites and the 8 web tests pass |
| Merge catalogues by key, not by line | 632 keys, 0 untranslated, `translate.py --check` passes (only 73 keys in all were written differently by both sides) |

Not covered by the trial: the LG and Samsung packaging and ES5 steps of `tools/check.sh`, and a real `build.sh` union (it used stub config fields). The trial also kept `HomeApps` and `Capabilities` whole for speed; this plan resolves them by hand instead, to keep upstream's platform fixes in them. Task 2 runs all of it for real.

Staged merges (one per upstream checkpoint) were considered and rejected. Conflicts arrive in the same places regardless, and they'd repeat the same keep-whole work at each stage without giving more checkpoints than the commits below.

## Global Constraints

- Work only on branch `merge/upstream-1.3` in worktree `../free-my-tv-merge`. Leave `tvos-redesign`, `main` and `../free-my-tv-ci-fix` alone until Task 8.
- Merge the pinned commit `a9e1027`, never `origin/main`, so a later fetch can't change what was tested.
- Push only to `mahittv`. Never `git push origin`: that's someone else's repo. Every `gh` command takes `--repo MahitP/mahitTV`.
- PR text has no bare `@name` and no bare `#N`: upstream's issue numbers would link to unrelated items here.
- `tools/check.sh` passes before every commit.
- Every commit ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. The PR body ends with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.
- On-screen text says mahitTV, never Free My TV.
- Catalogues change only through `tools/merge_i18n.py`, plus one local script for wording neither side has (reuse `translate.py`'s `load`/`save`). No translation subagents, no API, no `--fill`. New keys in pt, es, de, ru, th, tr get flagged for human review.
- Upstream's `CLAUDE.md` "Always" rules stay true: the setup app's order around the stock home screen, never turning off an app that saved a Wi-Fi network, never uninstalling or clearing system apps, and a working way back (*Original* and the watchdog). Take `HomeMode` as upstream wrote it, changing only what's named here.
- Never commit `config.properties`, `*.keystore` or any key.
- Installing on the TV, pushing, opening the PR and merging to `main` each need the user's OK at that moment. A push to `main` that changes `docs/` also publishes the website (`pages.yml`).
- Check `df -h .` before builds: stop under 2 GB free and ask. Don't free space without asking. Use `trash`, not `rm`, for anything outside the scratchpad.
- Say plainly what was only built and unit-tested versus seen on the TV.

## Feature Decisions

The rule: **mahitTV's interface wins; upstream's fixes and data sources come across.**

| Upstream feature | Decision | Why |
|---|---|---|

| Plex, Trakt, Stremio, Picks from, Watchmode, TMDB key on the TV, German services, api.tmdb.org | Port, Tasks 4 and 5 | All stay off until set up |
| Immich as a My Photos source | Port, Task 5 | Hidden until a server is configured |
| Clock 12/24, At power-on | Port, Tasks 5 and 6 | No mahitTV equivalent |
| Home cards and posters, background follows pick | Drop | Replaced by the Top Shelf |
| Status icons and mouse | Drop | Control Center shows this; TV is remote-driven |
| Recent Apps | Drop; `git rm RecentApps.java` | `RecentsOverlay` does this and already uses `HomeMode.forceStop` |
| Top-button reorder, app store shortcut, Android apps toggle | Drop | Dock, `topButtons`, `systemApps` cover these |
| Continue Watching from Watch Next (**D1**) | Drop for now; `WatchNext`/`WatchArt` stay in the tree, unwired | mahitTV has its own via `WatchLog`. Watch Next has better resume data and could feed the Top Shelf later |
| Home Assistant drawer (**D2**) | Drop; `git rm HomeAssistant.java` | The drawer no longer exists and you use Kasa |
| Self-updater (**D3**) | Keep inert, no Settings row, no `REQUEST_INSTALL_PACKAGES` | `schedule()` and `check()` return early without upstream's release key, which your builds never have |
| LG/Samsung additions (**D4**) | Port last, Task 7 | Your rule is features on both platforms, but no TV of yours runs it, so it's safe to stop before this |
| webOS clock screensaver and night dim | Drop | `saver.js` covers it, and upstream's `#dim` collides with Control Center's `#dim` |

Permissions after the merge are mahitTV's current set only, with `BLUETOOTH` listed once. `READ_TV_LISTINGS` and `BLUETOOTH_CONNECT` serve dropped features.
